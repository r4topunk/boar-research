## Outcome label (tools/label.mjs; Haiku 5.5-low, eval-lib runClaude, tools none, JSON schema)
Unit = (item, answer text exactly as shown, sources shown). Identical units share one label. Blind to mode and pack state (neither is in the prompt; the answer's own length/style is unavoidable).
Sources shown = the numbered context passages of the generation prompt(s) from the prompt dump (Succinct/Detailed: the system prompt's Context block; Deep: the union of the sub-answer Context blocks, de-duplicated, first-seen order), each as `[n] Title (cited)` when the title is in answer.cited, body as given to the model. 0 passages -> "(none)".
Expected answer = v0.1: bench/v0.1/refs/refs.jsonl `answer` + questions.public.jsonl `rubric`; cm: bench/selftest/<pack>/refs/refs.jsonl `answer` + questions.jsonl `rubric`.
System prompt (exact): "You are a strict grader of an offline phone assistant. You compare its answer with a reference answer and check whether the passages it showed the user contain that answer."
User prompt (exact; {Q} {GOLD} {RUBRIC} {ANSWER} {SOURCES} substituted):
"QUESTION:\n{Q}\n\nREFERENCE ANSWER:\n{GOLD}\n\nRUBRIC (what a good answer must contain):\n{RUBRIC}\n\nASSISTANT ANSWER (exactly as the user saw it):\n{ANSWER}\n\nSOURCE PASSAGES THE APP SHOWED WITH THE ANSWER:\n{SOURCES}\n\nDecide two things.\n(1) source_holds: true if at least one source passage states, or directly entails, the central answer-bearing claim of the reference answer; false otherwise.\n(2) label, exactly one of:\n- CORRECT_WITH_SOURCE: the answer gives the central claim of the reference answer correctly (minor omissions are fine; nothing central contradicts it) AND source_holds is true.\n- CORRECT_FROM_MEMORY: the answer gives the central claim correctly but source_holds is false.\n- HONEST_UNKNOWN: the answer says it does not have the information or declines, and does not assert an invented or wrong specific, and source_holds is false.\n- REFUSED_WRONGLY: the answer says it does not have the information or declines without giving the central claim, although source_holds is true.\n- WRONG_WARNED: the answer's central claim is wrong, missing or contains an invented or wrong specific, AND the answer carries a visible warning that it may be wrong or is not from the offline library (for example a line starting 'Not found in this phone's offline library').\n- WRONG_CONFIDENT: the central claim is wrong, missing or contains an invented or wrong specific, with no such warning.\nA warning line does not make a correct answer wrong: a correct answer with a warning is CORRECT_FROM_MEMORY or CORRECT_WITH_SOURCE. Judge correctness against the reference answer, not your own knowledge. Set confidence to \"clear\" or \"borderline\". Reply with the JSON {\"label\": ..., \"source_holds\": true|false, \"confidence\": \"clear\"|\"borderline\"}."
Re-check (GATE17S style): borderline -> call B with the source passages in reversed order (renumbered); if B's label differs -> call C (original order); majority of A/B/C (three different labels -> A stands, flagged). Retry an errored call once. Cap Haiku 400 in total (A calls first, then B, then C; a B/C call that would pass 395 is skipped and the unit is flagged single). Ledger CALLS.md.

## Predictions (frozen)
P1 pack ON vs OFF raises CORRECT_WITH_SOURCE in every mode, most in Succinct.
P2 OFF yields more WRONG_CONFIDENT in Detailed and Deep than in Succinct.
P3 HONEST_UNKNOWN is the most common OFF outcome only in Succinct (in Detailed and Deep another label is the most common OFF outcome).
P4 Deep never improves OFF over Succinct: Deep OFF correct share (CWS + CFM) <= Succinct OFF correct share.

## What would change a product default (frozen)
- Default mode stays Succinct unless Detailed (or Deep) has an ON correct share >= Succinct + 0.10 AND an OFF WRONG_CONFIDENT share <= Succinct's + 0.05.
- Deep Research stays hidden unless Deep ON correct share >= Succinct ON + 0.10 (DEEPMODE said U lower).
- The OFF honesty surface needs a change (wording/warning default) if, in the default mode, OFF WRONG_CONFIDENT >= 0.25 of items, or REFUSED_WRONGLY >= 0.10 with the pack ON (the pack held it and the user was refused).
