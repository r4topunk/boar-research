## Q1 (code, 0 compute) — answered: an index-only column changes BM25 ranking only
The index is read only in `bm25Candidates` (wikiPack.ts:663-671). The relevance gate (wikiPack.ts:856-858) computes coverage over `title + text` taken from the article blob via `materialize` → `hit()` (:683, :577-596, :497-506); onTopic (context.ts:702-746) reads `chunk.title + chunk.body` (body = section + passage, packs.ts:208-214) from `onSubject` (answer.ts:974-981) in the keep step (answer.ts:1037-1041); compressContext (context.ts:1465-1563) also title + body only. **So doc2query as an index column cannot help the 95/137 items that fail the gate or the keep step** unless the gate also sees the expansions. X2 implemented (d2q.vs-cut7.patch sha 10b440ea…, +25/−6 lines, default off): `BOAR_D2Q=x1` searches `fts_d2q(title, section, body, questions)` (questions weight 1); `BOAR_D2Q=x2` also reads the questions from a `d2q` table in `hit()` as an `expansion` field counted by the gate and onTopic, never shown in the prompt. Off-mode identity 480/480 item-passes vs the tk2off reference (only the "Today is …" date line differs on 7 items); smoke on a medlineplus copy with one expanded chunk: OFF/X1/X2/OFF2 match 20/20; rebuilt index token-identical 3042/3042 rows.
