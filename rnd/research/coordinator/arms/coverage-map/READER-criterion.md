# READER criterion (FROZEN 2026-10-22 21:0x, before any autopsy read or generation): delivered but unused

Question: with the F1b configuration (13-pack kit, cooking/money chunk vectors, gidf, head pass a2 + extra), 45 of 92 real items have the key fact in the kept context, yet the answers did not improve: 9 of the 14 newly delivered cooking/money facts still end as warned memory answers, and the funnel's S4 class (fact kept, answer wrong) persists. Why does the 1.7B not use a delivered chunk, and which engine-side change makes it use it?
Sets (dev): the 14 newly delivered cm items (answers-f1b.json), the S4 items under F1b (fact present in kept, judge correctness < 3.5 or declined; derive from answers-f1b / answers-compose rows with the FACTPRESENT flag), and the 18 "present in both" items as the no-harm set. Traces: sefix/ans-traces (F1b) and compose/screen traces (ARM-G).
Phase 1 autopsy (0 LLM): per item: the kept chunks (which one holds the fact, its position, its length after compression, whether it is an SE answer chunk without its question), the answer text (does it state the fact? cite [n]? which [n]?), the engine's post-processing (weakSources / warned / cited fields, grounding reason codes, compression context:a->b), and a class: (a) model ignored the chunk and answered from memory, (b) model used it but did not cite so the engine warned it, (c) the chunk was compressed below the fact sentence, (d) the chunk is an SE answer whose question is missing so the model cannot connect it, (e) the fact is phrased so the judge's rubric does not match (ruler issue), (f) other.
Phase 2 synthesis: ≤ 3 reader-side fixes with switches (candidates, not prescriptions: keep the SE question title as the chunk header in the prompt; raise the compression floor for chunks that hold a lexical match of the query; cite-or-ground rule change so an uncited but supported answer is not warned; a one-line instruction in the sources block for SE threads; pin the fact-bearing chunk first), each with expected effect and risk.
Phase 3: generation on the mini for each fix (MAIN 97, F1b configuration + the switch), divergence-first vs F1b, Haiku 5.5-low judge.v1 N 4 both orders, cap 100 per fix (≤ 300 total), paired ΔU vs F1b on changed items (B 2000 seed 11), CE-unwarned, the target items' correctness before/after, the no-harm set.
Rule: a fix READS iff ΔU vs F1b ≥ +0.02 with CI low > −0.01 on changed items AND CE-unwarned not up AND the target items' mean correctness +0.5 or better; LEVER-CANDIDATE iff additionally vs the K3 control over all 97 ΔU ≥ +0.02 with CI low > −0.01.
Prediction: classes (a) + (b) dominate (≥ 60 %); the cite-or-ground change and the SE question header are the two that read; best fix +0.03…+0.06 vs F1b on changed items.
