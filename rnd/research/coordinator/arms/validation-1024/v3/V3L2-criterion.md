## What is generated (mini queue jobs v3-s, v3-splus; night/tools/mk_jobs.py sha 3a5f1775, night/tools/v3_stage2.py sha b5ca96ce)
- Items: the 48 F8 pairs of retbench/items/f8-48.json (8 per pack: boar-crypto, boar-factbook, boar-firstaid-en, boar-medlineplus-en, boar-visa-en, boar-wikivoyage-en); questions from coverage-map/searchpar/r5/qform.chain.jsonl.
- System: ENGINE-RC as tools/rc-env.sh defines it (tree kiln-local/rs-RC synced to the mini, RC kit = K13 with w78pf simplewiki + travel and the shaped factbook, RC env, RC settings), Qwen3-1.7B Q4_K_M, llama-server b11010 CPU -t 4, seed 42, --reasoning off, adapter be/adapter-litedecline.ts with --dump-prompts, LITEDECLINE_OFF=5, detector :8094 mmBERT v3b.
- Stage 1: the 48 turn-1 questions, no history (group 00-turn1).
- Stage 2 (built on the mini from stage-1 traces): the 48 follow-ups with item.history.turns = [user: turn-1 question, assistant: the turn-1 trace answer.text exactly as shown (banner line and [n] markers included)]; an empty turn-1 answer leaves only the user turn. This is what ChatScreen sends (src/ui-android/ChatScreen.tsx: messages with text.length > 0, the last VERBATIM_MESSAGE_COUNT = 6, assistant text through stripThinking, summary null before turn 7); the adapter passes it as AnswerContext.history {summary: null, turns} (be/trace.ts answerContext). RS_STICKY stays unset (not in ENGINE-RC). Deviation, declared: the app's turn-1 text is whatever streamed to the screen; the desktop twin uses the final answer.text.
- Personas: S = Succinct as shipped (personalityId succinct, adapter persona sha 5e0de1c7); S+ = v2/personas/splus.json (file sha 328ecb38, adapter persona sha 4c2773b5). Both are generated tonight (96 answers each); S+ is labelled only if V2 ADOPTs it.

## Labels (v3/label_v3.mjs sha b9eab642; Haiku 5.5-low, eval-lib runClaude, tools none, JSON schema)
Unit = one follow-up answer (persona, F8 id, turn-1 assistant text as sent, follow-up answer). Units built by v3/prep_agg_v3.py prep (sha 94d55981). Reference = the F8 item's gold_quote (the turn-1 source's fact that answers the follow-up).
System prompt (exact): "You are a strict grader of an offline phone assistant in a two-turn conversation. You judge only the assistant's answer to the follow-up question."
User prompt: exactly the `prompt` template in label_v3.mjs (sha above): conversation as sent, follow-up question, reference fact, answer as shown; fields on_referent (true iff the answer is about the turn-1 subject) and label CORRECT | HONEST_UNKNOWN | WRONG_WARNED | WRONG_CONFIDENT (warning lines named: "Not found in this phone's offline library", "The passages found don't support this answer"), confidence clear | borderline.
Sampling: call A on every unit; A borderline -> call B (same prompt, fresh call); B differs from A in label or on_referent -> call C; final per field = majority of A/B/C (three different labels -> A). An errored call is retried once; every invocation counts.
Order and cap: persona S first (A, then B, then C), then S+ (only if adopted). Cap 220 invocations in total (LABEL_CAP=220, counted from the labels file). Expected: S 48 A + at most 48 B + at most 48 C = 48..144; S+ adds 48..144 and is cut at the cap (A calls of S+ before its B/C).
Command (morning, only if named): `python3 -I v3/prep_agg_v3.py prep v3/judge S=night/fetched/v3-s [SP=night/fetched/v3-splus]` then `LABEL_CAP=220 node v3/label_v3.mjs v3/judge/units.json v3/judge/labels.jsonl S[,SP]` then `python3 -I v3/prep_agg_v3.py agg v3/judge v3/judge/labels.jsonl`.
