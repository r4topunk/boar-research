### Conversion (stage 2, in budget)

### Load findings (what the fork needs on CPU)
- `stripped.gguf` does NOT load on the CPU build: `create_expert_tensor_from_manifest: backend has no alloc-only buft, cannot synthesize stripped expert tensor` (alloc-only buffer type exists only in the Metal backend, ggml-metal.cpp). So the stripped file is Metal-only.
- Full GGUF + `--moe-experts experts --moe-slot-bank N` with default mmap: `MoE slot tensor 'blk.0.ffn_gate_exps.weight' is not CPU-addressable`. With `--no-mmap` it loads and streams (expert tensors are virtualized, the 9.8 GiB in the GGUF is never read). Working command: `llama-completion -m <full gguf> --moe-experts experts --moe-slot-bank 1280 --no-mmap -t 4 -c 4096 --temp 0 --top-k 1 -no-cnv -n 128`.
- Bank arithmetic: per-expert packed stride 1,007,616 B (0.961 MiB, gate+up+down). Loader limit bank <= 32 x 40 layers = 1280 slots = 1280 x 0.961 MiB = **1.20 GiB**. A 4 GiB cache would be 4,443 slots, above the loader's hard limit, so the cap is structural at 1.20 GiB (the criterion's <= 4 GiB is met by construction; larger banks are not accepted). Consequently there is no "uncapped LES" setting; config (b) = fork in stock mode (no `--moe-*`, mmap, all experts resident) which doubles as the identity reference for the fork's base.
- Defaults at run: lookahead prefetch off, decode-cache off (env `LLAMA_MOE_LOOKAHEAD_PREFETCH`/`LLAMA_MOE_DECODE_WINDOW` unset); io_threads=4, preadv on. Not tuned.
