# WARNSPEC: the unsafe-answer warning for health turns the model answers alone (product spec + 0-LLM counts; 2026-10-16)

TL;DR: a WARN banner goes on every finished turn that is **model-generated AND health-shaped**. The banner has three tiers, picked by grounding: no offline source, a source the answer goes beyond, or sourced (v2 names). With HEALTHGAP r2 on, it fires on 3/64 probes for the 4B (h21, n12, vit-hlt-003), 4/60 on v0.1 and 36/180 self-tests (4B+X2b = 1.7B+X2b, the same count). On cut 7 without HEALTHGAP it covers all 6 unsafe 2B answers and both jev-flagged 4B answers. False positives: 4 non-health questions on the 180 and 0 on v0.1. jev cannot calibrate it (AUC 0.46). 0 judge calls; jev 60 requests, [usage detail removed].

## 1. The rule (over a finished turn; trace fields = `route.reasonCodes`, done `receipt.modelId`, `retrieval.kept`, done `cited`, final text)
- **M, model-generated** = outcome success, the text is non-empty, `receipt.modelId` ∉ {grounding-guard, extractive, none, places, calculator, small-talk} (the engine's `NOT_A_MODEL` set plus small-talk), no `answer:*` code, no code containing `declined`, no `instant:final`. This excludes every deterministic layer: cards (`answer:first-aid-card-*`, `grounding:fa-card-*`), `answer:facts-*`, `answer:calculator-*` and `answer:temperature-conversion`, `grounding:health-no-source`, `grounding:health-no-dose`, `grounding:health-dose-excerpt`, `grounding:health-extractive`, and the compact-model declines.
- **H, health-shaped** (any of the following): `detector:fire` · `detector:p=` ≥ **0.05**. On the 100 self-tests of the five non-health packs the max is 0.03, and the 0.2 fire threshold misses the health self-tests at 0.05–0.19 · any `healthgap:*` code · any `grounding:health-*` code · `isSafetyQuery(q)` (context.ts; the existing lexicon) · the **WARN lexicon** on q (tools/warnspec.py `WARN_LEX`: drugs and dosing, poison/toxic/venom/CO/ppm, ≈ 60 disease, condition and symptom words, body/test words, care-seeking words, plus a red-flag line "lost/dropped N kg in…", "without trying") · a kept chunk from a health pack (in the engine: packId ∈ {boar-medlineplus-en, qa-health-se, boar-firstaid-en}; in the traces: the hosts medlineplus.gov, medicalsciences.stackexchange.com and archive.org/details/army-*).
- **WARN = M ∧ H**, with exactly one tier:
  - `warn:no-source`: `retrieval.kept` is empty (in practice this is `grounding:no-source-memory` / `grounding:no-good-source` with 0 kept).
  - `warn:beyond-source`: kept > 0 and (`cited` is empty, i.e. `grounding:uncited-warning` / `grounding:uncited-on-topic`, **or** the v2 coverage rule fails). A content sentence (≥ 5 words, after stripping the app's preface and the engine's emergency tail) counts as cited if it carries `[n]` or `[n]` follows its full stop. The rule passes only if the **first content sentence is cited AND ≥ 50 % of content sentences are cited**. This means uncited sentences, not a contradiction check.
  - `warn:sourced` (v1 name `general`, renamed because answer.ts calls weak_sources the "general knowledge" seal): kept > 0, cited, and the coverage rule passes. Grounding does not make an answer safe: vit-hlt-003 is cited and wrong for the 2B.

## 3. jev calibration (tools/jev_cal.py; 60 requests, [usage detail removed], cache aggregates/jev-cache/)
Question: "should the app put a caution banner above it…". WARN 30 (4B ON/v0.1/X2b, seed 616) vs non-WARN health 30 (15 deterministic probe answers + 15 non-WARN 4B+X2b firstaid/outdoors model answers). p ≥ 0.5: WARN 10/30 (median 0.41), deterministic 10/15 (0.50), non-WARN model 4/15 (0.40); **AUC 0.46** (0.56 vs non-WARN model answers). jev reads the topic and the urgency, not the grounding: it rates the fixed health cards as more banner-worthy than model answers. It is not a usable calibrator or second gate for WARN, so the rule stays reason-code only.

## 4. UI note
1. The banner sits **above the answer text** in the message bubble, inline (no toast). It is **shown at stream start**: H, M and kept are known before generation, so it starts as no-source (0 kept) or beyond-source, and `done` may only move beyond → sourced. The tier is **stored with the message** and never recomputed on restore or share.
2. One banner per message, tier copy from §1; the emergency-number line and cards keep their own place below it.
3. Receipt and trace: add `warn:<tier>` to `reasonCodes` and a **new** `done.warn` field (not a `warning` event code). Non-WARN turns keep weak_sources and uncitedPreface byte for byte. An "Answer anyway" re-ask is M and gets WARN.
4. **`deps.warn` default = off** until the v0.3 check in §6 passes, then on for every tier. With it off (or set to false), the current `weak_sources` seal is restored byte for byte.
5. WARN never changes routing, the detector, HEALTHGAP, NUMGUARD, cards or texts. A WARN turn has no deterministic answer by construction.

## 5. Port-spec lines (drafted as PORT-SPEC-HEALTH-PATH-2026-10-15.md §10, DRAFT)
- M (known before generation, confirmed at `done`) = modelId ∉ NOT_A_MODEL ∪ {small-talk} ∧ no `answer:*` ∧ no `*declined*` ∧ no `instant:final` ∧ success ∧ non-empty text.
- H = `detector:fire` ∨ detector p ≥ 0.05 ∨ `healthgap:*` ∨ `grounding:health-*` ∨ isSafetyQuery(q) ∨ WARN_LEX(q) (word boundaries as `(?<![\p{L}\p{N}_])…(?![\p{L}\p{N}_])`: JS `\w` is ASCII even with /u, and Kotlin needs UNICODE_CHARACTER_CLASS) ∨ a kept chunk with packId ∈ {boar-medlineplus-en, qa-health-se, boar-firstaid-en}.
- Tier: 0 kept → no-source; kept ∧ (0 cited ∨ first content sentence uncited ∨ < 50 % of content sentences cited) → beyond-source; else sourced. No model-based gate; reason codes only (WARNSPEC §3).
- Emit `warn:<tier>` in reasonCodes + `done.warn`; render the tier copy above the answer from stream start and store it with the message; suppress `uncitedPreface`/`weak_sources` on that turn.
- Parity goldens = aggregates/warnspec.json rows (probes 64 ON: exactly h21, n12, vit-hlt-003; v0.1: the 4 ids; 180: 36 ids per model); `WARN_LEX` is normative.
