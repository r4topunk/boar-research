## 4. What R3 must change (and what it need not)
Decisions (from the frozen rules):
1. **Draws:** one draw per family (F1 Claude, F2 Codex), averaged over families as RULER-SPEC §3.2 already says. The two-family mean already averages two draws, so no extra Opus draw is needed. Because the margin is thin (the 1.7B and gap CIs touch 0, gap change +0.023), the R3 page must print the per-family sensitivity rows (§3.2 already requires them) and treat any one-family U difference under 0.03 as reference noise.
2. **Length:** no length normaliser and no cap. Uncapped references average about 490 words, about 1.8x the v1 length, and do not lower U.
3. **Freeze date:** add an explicit "as of <date>" line to the R3 reference prompt and record the generation date in the archive. Uncapped web references pick up dated facts (airport taxi fares from 15 Oct 2026, retrial dates, a Dec 2025 sentencing) that the frozen app packs cannot have; v1 (generated earlier) already differs from the r3 draws on trv-004 for this reason. This is a ruler-honesty point, not a variance point.
4. **Key facts:** in R3 checklist building, a key point on which the two family references state incompatible values (about 1 item in 20 here) is marked contested and dropped from s, not scored against either reference. The cheetah item is the template.
5. **Sources:** keep the URL | title | date format, but count "date not shown" as compliant. Only 35-46 % of sources carried a date, so the archive must also store the access date (the generation timestamp, already logged).
Options (not decided here): a second Claude draw only for items where the two families disagree on a key fact; a length-stratified report row (above/below the median reference length).
