## 1. Findings, by impact
**F1 (high). Resume reuses rows from other traces or another judge model, and the fail-closed checks still pass.** `boar-eval/harness/judge.mjs:89` builds the "done" set from `queryId|order` alone (ignores tracesSha256, questionsSha256, refsSha256, judgeVersion, model); `arms/deepthink/tools/shard_judge.sh:39-43` prints the model set but never asserts; `arms/_lib/check_judgments.py` checks completeness only. Repro A: copy `deepread/deep35-R450.judgments.jsonl` (Opus) to J.jsonl, run judge.mjs on `deeppar/bmoe-R450.traces.jsonl` with `--judge-model claude-haiku-5-5 --dry-run` → `0 calls to do (114 done)`. Repro B: same file as `out.shards/shard-0.jsonl` → shard_judge rc 0, `check ok rows=114`, 0 calls, all rows claude-opus-5-5 from the deep35 traces. In practice: `packs/selftest-runs/st-qa-cooking-se-cut7-nopack-s42.judgments.jsonl` holds 30 rows against the old traces/questions/refs and 10 against the new (item 003 splice) — benign (only 003 changed, its rows are new; WAVE3 cooking Δ +0.010 stands), but any re-run into the same path is exposed. Fix: compare each ok row's tracesSha256/questionsSha256/refsSha256/judgeVersion/requestedModel with the current run, exit 7 on STALE unless `--allow-splice`; write `requestedModel` into rows; shard_judge's node check asserts one judgeModel and one tracesSha256.
**F2 (high, latent). `arm.sh scales` returns rc 0 after writing an empty L2 aggregate.** `arms/_lib/arm.sh:17,137,152`: bash 3.2 + `set -u` aborts on `"${QA[@]}"` when QUESTIONS is unset; `:145-155` never checks `fm`/`paired_gap`/`jq` return codes, paired_gap stderr → /dev/null. Repro: `CONTROL_CHECK=warn arm.sh conf scales "42 43"` with control seed 43 missing → rc 0, 0-byte `L2-P-2seed.opus.json`, 1-byte paired_gap JSON. Evidence in the repo: `dt512/aggregates/L2-H-3seed.opus.json` (0 B) and `paired_gap-H{D,T}-3seed.json` (1 B), 10-10. No reported number comes from these (SEEDVAR used seedvar.mjs; every current arm.conf sets QUESTIONS). Fix: `${QA[@]+"${QA[@]}"}`; `v=$(fm …) || return 5` etc.; `[ -s …opus.json ] || return 5`.
**F3 (high, exposure). The blind pre-commit hook is easy to bypass.** Blocked correctly: `bench/v0.3/questions.v03.jsonl`, a single-line item whose id field (v03-travel-01) precedes its question field. Passed with rc 0 when they should be blocked: `"question"` before `"id"`; pretty-printed multi-line item; `v03-travel-1` (one digit); `V03-…`; `questions_v03.jsonl`, `questions.v03.jsonl.bak`; `blind/questões.jsonl` (git quotes non-ASCII paths → `(^|/)blind/` misses `"blind/quest\303\265es.jsonl"`); any V-para-style id (`vit-hum-001`); `bench/v0.2/questions.jsonl`. The boar-rnd copy `rnd/tools/hooks/pre-commit` is stale (a `v03p-qa-travel-se-001` line: rc 0 there, rc 1 in boar-eval). Affects the v0.3 exposure guarantee (BENCH-V03-SPEC §6 R3) and the other blind sets. Fix: `git -c core.quotePath=false diff --cached --name-only --diff-filter=ACMR | grep -iE '(^|/)blind/|questions[._-]?v0[2-9]|refs/(refs|web__)[^/]*\.jsonl|refs/raw/'`; id regex `"id" *: *"(v0[3-9]p?|vit|hf|es|chat|meta)-[a-z0-9-]+-[0-9]{1,3}"` case-insensitive; copy to boar-rnd.
