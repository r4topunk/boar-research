# MINICPM-VERIFY: primary-source check of the MiniCPM5 leads

TL;DR: The vendor numbers are real, but the leads read them wrong in four places. (1) The 1B's only tool number is BFCL v4 = 25.15 in **thinking mode**, which ties Qwen3-0.6B. The 66.6 belongs to the **2B**, a separate model trained for deep thinking only. (2) The AA "17.9" is an older Index version. On the current v4.3.2 pages, MiniCPM5-1B scores 9 (marked as an estimate) vs Qwen3-4B-2507 Instruct 7 and Qwen3-1.7B 5 (both also estimates). (3) AA-Omniscience −1 comes from abstaining (hallucination rate 1 %). It is not knowledge. (4) Thinking-off works by prefilling an empty `<think></think>` block, and only when `enable_thinking` actually reaches the template, which explains our 2026-10-02 node-llama-cpp failure. The "92 % runaway" figure is a primary GitHub issue, but it was measured on the **2B Q4_K_M with thinking on, coding (HumanEval+)**.

Checked 2026-10-19 by an Opus verifier. Sources: HF cards and raw files under `openbmb/`, the OpenBMB/MiniCPM GitHub (docs and issues), the ggml-org/llama.cpp source and PRs, and Artificial Analysis articles and model pages. The 1B benchmark table exists only as an image, so I read the image.

## Bottom line for an agentic offline research assistant

- **The 1B is not a tool-calling upgrade.** Its own vendor table gives BFCL v4 = 25.15 in thinking mode, which ties Qwen3-0.6B (25.43) and Qwen3.5-0.8B (25.53). No-think tool numbers do not exist (rows 1c–1d, 2c). The strong agentic figures (BFCL v4 66.6 > Qwen3.5-4B 56.8, τ² 97.1, GAIA-Text 88.7) belong to the **2.5B, thinking-only** 2B and are vendor-reproduced. The source tables include neither Qwen3-4B-Instruct-2507 nor Qwen3-1.7B, so no head-to-head on tools exists (2a–2b).
- **Ranking against our Qwen models (AA Index v4.3.2, the only common page):** MiniCPM5-2B (reasoning) 12 > MiniCPM5-1B (non-reasoning) 9* > Qwen3-4B-2507 Instruct 7* > Qwen3-1.7B (non-reasoning) 5* (* = AA estimate). The Index is weighted toward reasoning and agentic tasks, not grounded reading. Our own 40-prompt replay showed no quality gain for the 1B over Qwen2.5-1.5B (4a, 4d).
- **Knowledge ≈ abstention.** 1B Omniscience −1 with a 1 % hallucination rate; 2B attempts 29 % of questions at 8 % accuracy. Both models refuse rather than invent, which suits a pack-grounded design. But they bring almost no closed-book fallback, so retrieval recall bounds the answers more tightly than with Qwen3-4B (4b–4c).
- **Thinking off is a template prefill.** Pass `enable_thinking=false` so it reaches the Jinja context (`--reasoning off` on current llama.cpp), or prefill `<think>\n\n</think>\n\n` ourselves. Leaving the variable undefined lets the model think, which is what bit our 10-02 run. Only the 1B has a vendor no-think profile (temp 0.7, top_p 0.95). The 2B is deep-thinking-trained only (5a–5c).
- **The tool loop on llama.cpp is feasible but fragile.** XML calls work through the dedicated parser (merged 2026-06-28; present in b11010). Results go back as a user turn wrapped in `<tool_response>`. The official GGUF still flags the `<function>`/`<param>` tokens as special, so any engine that detokenizes outside llama.cpp's chat parser (llama.rn, node-llama-cpp, our own Kotlin/Swift) must keep special tokens or it will see stripped tags (5d–5e).
- **Runaway is a family-level risk, so gate it before any agentic test.** Vendor: −29 pp max-token hits after RL, which means hits were common before it. #374: 2B Q4_K_M with thinking on runs away 92 % at rp 1.00 and 11 % at 1.15. Our 1B replay: 8/120 to the cap. Vendor sampling is `min_p 0.0` (ours 0.05) and repeat penalty 1.05 (2B card). Any MiniCPM5 arm must freeze these flags and score cap-hit rate as a failure (1f, 6, 6b).

UNKNOWN: whether the 1B's BFCL v4 and the 2B's BFCL v4 used the same categories or harness. BFCL in no-think mode for either model. Whether `--reasoning off` exists at b11010 (it exists on master). Omniscience for Qwen3-4B-2507 and Qwen3-1.7B (not shown on their AA pages). Repeat-penalty behaviour of the 1B.
