# JEV-LOOP — moving the loop's recurring decisions out of the coordinator's context (proposal, 2026-10-13 23:0x)

Source: @beamnxw, "Loop Engineering + Jev Engineering: Cut Your Claude Bill" (x.com/beamnxw/article/2108101310515925217, 2026-10-08). Read by the coordinator; summarised here, not quoted.

TL;DR: the article's technique is **three paths for every recurring decision in an agent loop**: (1) exact checks in code first (ids, hashes, timestamps, exit codes), (2) a typed cheap classifier (jev) for decisions that need reading meaning, (3) the expensive model only for accepted work, with a bounded brief and an evidence-based completion check. Measure in shadow mode, keep one compact record per decision, track cost per accepted completed task. Our loop already does (1) and (2) for *judge admission* (0-call gates, L1 futility rule, jev fact gates). It does **not** do it for the **tick itself** (37 of 121 ticks were idle or wait-only and each paid the full §2 step-0 state read), nor for **subagent deliveries** (the coordinator reads every report in full), nor for **hypothesis dedupe** against CLOSED.md (the 10-13 ledger audit found 46 verdicts without a CLOSED row and 8 disagreeing rows). Proposal: an exact pre-tick change detector, a jev completion check on deliveries (shadow first), a jev dedupe/consistency pass, and a `decisions.jsonl` ledger. No PreToolUse jev gate: our hard boundaries (push, upload, blind/, Docker, :8094) are better as exact deny rules.

Dialect note (skill `jev`, references/gateway.md): the article uses the TypeSafe SDK (`system_one`, `Noul`, `TYPESAFE_API_KEY`, `jev-1.13.0`). Here: `POST https://ai-gateway.vercel.sh/v1/evaluate`, model `typesafe-ai/jev`, `"type":"boolean"` → `answers.x.probability`, `usage.inputTokens`, one key (`VERCEL_AI_GATEWAY`). No version pinning through the gateway → keep a fixed regression set per question.

## 1. What the article proposes (mechanism, not quotes)
| Step | Mechanism | Our status |
|---|---|---|
| Inventory | list the semantic questions asked between productive actions, with frequency and the information that answers them | not done at the tick level; done implicitly for judge admission |
| Order of paths | exact code check → semantic classifier → expensive agent; the classifier also costs, so it only sees items that changed | judge path: yes (replay/hit-rate/KLD gates, L1 rule). Tick path: no (model reads state every wake-up) |
| Typed routing | `choice` with an explicit `other`, `boolean` for evidence, thresholds chosen from 30–50 labelled historical cases, shadow mode, log proposed + actual route, count misses as well as wrong admissions | jev used for fact gates with stated caps; never for routing the loop's own decisions |
| Queue identity | item id + content hash + classification record; claim before launch; an unchanged item must not spawn a second run | arms have criteria shas and `arm.sh launch` refuses without one; no hash on *deliveries* or *hypotheses* |
| Tool gate | PreToolUse hook classifies command effects; unclear → ask; destructive boundaries stay as exact rules | rnd pre-commit hook (blind plaintext) only; no PreToolUse hook in the project |
| Completion check | GOAL.md with required evidence + stop conditions; code checks exit codes/file existence; jev asks "does the evidence address the requirement"; Stop hook + attempt counter | criteria have a definition of done; the coordinator verifies deliveries by reading them (Opus/Fable tokens) |
| Decision budget | cost per accepted completed task, including corrections caused by bad routing; one compact record per decision | pipeline metric = V-para floor-adj points per 1,000 judge calls (BAR-TABLE §3); no per-decision ledger |

Volume check (why jev, not Haiku, for D4–D6): deliveries ≈ 5–15 per day, hypotheses ≈ 2 per META tick, sweep candidates ≈ 20–100 per week, consistency pass 154 once → total < 1,000 requests per week ≈ **[usage detail removed]–0.20** at 4k input tokens each. Haiku would cost ≈ 1 min per 20 items and the weekly rhythm; the real saving is the coordinator's context on idle ticks and unread reports, not the classifier's own price.

## 3. Decisions / Options / Tasks
**Decisions (fix direction)**
- D-J1: the tick's step 0 becomes one exact precheck; the model reads state only on a change. Idle ticks are one tool call.
- D-J2: waits on mini runs become event-driven (`Monitor` on STATUS with failure signatures + fallback wake-up ≥ 20 min), not fixed polls.
- D-J3: jev enters the loop only for D4 (completion check) and D5 (dedupe/consistency), both in shadow mode until agreement with the coordinator ≥ 0.90 on ≥ 30 labelled cases; thresholds p ≥ 0.8, unsure = fail (skill recipe #5).
- D-J4: every routed decision writes one line to `coordinator/decisions.jsonl` (tick, decision id, inputs sha, jev values if any, route, outcome, tokens/calls it saved or spent). The pipeline metric gains a second number: **judge calls + coordinator ticks per adopted point**.
- D-J5: no jev tool gate; D8 as regex deny rules in a PreToolUse hook (project `.claude/settings.json`).

**Options (exploration, not now)**
- jev `score` on the Opus judge rationales as a drift watch on the judge itself (judge.v1 bytes fixed, but Opus moves): re-score a fixed 20-rationale set weekly; flag if the distribution shifts.
- jev as a pre-filter on which v0.2 items a slice should contain ("items where the control already scores ≥ 0.9 cannot show a gain") — a cheaper slice than random20 for prompt arms; needs a criterion because it touches item selection.
- `/goal`-style completion for the loop's weekly digest (evidence in transcript), if Claude Code's goal evaluator is cheaper than a Fable turn.

## 4. Cost framing (article's formula applied here)
Cost per adopted V-para point = (Opus + Haiku judge calls + mini hours + coordinator ticks + jev $ + corrections caused by a bad admission) / adopted points. Cycle 10-11 → 10-12: 0 points per 1,180 judge calls and ≈ 120 ticks; the pack line 10-13 adopted +0.032 (single pack, L2-confirmed) at ≈ 1,840 Opus + 2,500 Haiku. The tick overhead is the term the article attacks and the only one this proposal changes; judge admission stays as it is.
