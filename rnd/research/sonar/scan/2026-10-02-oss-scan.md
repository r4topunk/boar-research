# OSS scan: offline / on-device small-model RAG components vs BOAR (2026-10-02 night)
TL;DR: 45 components scanned in three clusters (web, licenses checked at the source) plus a level-0 test on our own data for 6 rerankers.
- **#1: a cross-encoder relevance check on the passages that reach the prompt.**
  - `bge-reranker-v2-m3` (Apache-2.0, 438 MB Q4_K_M) separates helpful from unhelpful prompt passages at **AUC 0.912** (our best cheap signal: 0.773).
  - It scores all 4 confident-wrong target passages at **0.01–0.12** (helpful median 0.77). No cheaper model does that.
  - Phone cost is the open question (182 ms/pair on M1 CPU).
- **#2:** logit/entropy routing (the Jev family) + an urgent **llama.rn ≥ 0.13.0-rc.5** fix (BOAR pins rc.4, whose `n_probs` are post-sampling and stale).
- **#3:** an MIT sentence pruner (OpenProvence) in place of `compressContext`.
- **#4:** build-time Doc2Query-- questions in FTS5 (zero phone cost).
- **#5:** a small multilingual router (mmBERT-small fine-tune, with Laya as a teacher/baseline, not shipped).
- Skip: HyDE/query2doc on ≤ 4B, Provence (non-commercial), multi-hop agents on the phone.

Policy: fast iteration (r4to 2026-10-02): L0 mechanism → L1 targeted slice → L2 full v0.1 → L3 v0.2. Slices: **KEY** = in-kit-key, **NOKEY** = in-kit-no-key, **OUT** = not-in-kit, **RT** = routing. Phone numbers are published figures (cited) or estimates (basis stated).

### #1 details: L0 already run (`sonar/exp/25-rerank-l0/`)
- **Data:** the 53 (question, passage) pairs that reached the Android 4B's prompts (`and-qwen-s44`), labelled helpful / same-subject-unhelpful / off-topic by an independent Opus rater (`exp/19`).
- **Never-empty drop:** drop below the lowest helpful score, always keep each item's best passage. Speed is on M1 CPU, 4 threads (llama.cpp via node-llama-cpp 3.21.1, `createRankingContext`).

- **Reading:** phone-sized rerankers beat cosine on easy cases but not on the hard class (same subject, asked fact missing), which is exactly where the 4B writes memory claims. Only the 0.6B multilingual model separates those cases.
- **Phone path:**
  - (a) run bge-m3 only on the ≤ 3 final prompt passages, as a "does any passage answer?" gate. ~1.5–3 s on Android (est.; Cluster A's anchor: MiniLM-L6 forward ≈ 28–54 ms on OnePlus 12 / Galaxy S24, scaled by compute); +438 MB RAM, a problem next to the 4B on an 8 GB phone.
  - (b) **distil** bge-m3 into MiniLM-L12/gte on pack-specific (question, passage) pairs generated at build time. That needs training; the teacher labels are free.
- **Next (L1, minutes):**
  - rerank the reconstructed raw pools of v0.1 items (exp-18 harness) and measure key-in-context at `pre` when the reranker picks the top-3 instead of `onSubject` + compression order;
  - flag items whose max score < τ and compare with the judge's CW items from s42/s43/s44 (no new judging).

### #2 details (for Anvil; routing is Anvil's front)
- **llama.rn issue #401:**
  - `n_probs` returned **post-sampling** probabilities, and `completion_probabilities` were **stale across calls**. Fixed in **v0.13.0-rc.5**: use `post_sampling_probs: false` ([issue](https://github.com/mybigday/llama.rn/issues/401), [release](https://github.com/mybigday/llama.rn/releases/tag/v0.13.0-rc.5)).
  - `boar-app` `package.json` pins `"llama.rn": "^0.13.0-rc.4"`. Any on-device Jev score built on rc.4 probabilities may be silently distorted; desktop node-llama-cpp is unaffected. Check `node_modules/llama.rn/package.json` after install: `^` on a prerelease may resolve to rc.4 exactly.
- **Evidence:**
  - AdaRAGUE benchmarks 35 adaptive-retrieval methods: simple uncertainty scores match complex pipelines ([arXiv 2501.12835](https://arxiv.org/abs/2501.12835), [code, MIT](https://github.com/s-nlp/AdaRAGUE));
  - Probing-RAG: a 5 MB MLP on hidden states skips retrieval 57% of the time ([arXiv 2410.13339](https://arxiv.org/html/2410.13339); no code);
  - UAR: an intent classifier on last-layer states = chat vs search ([repo](https://github.com/xiami2019/UAR); license UNKNOWN);
  - SKR's labelling: "search" only when the no-context answer is wrong ([repo](https://github.com/THUNLP-MT/SKR); license UNKNOWN).
- **L0:** AUROC of the Jev label logit and of mean token entropy for "needs search", on Compass's chat slice + v0.1 (no judge: label = no-context answer matches the key).

### #5 details
- **Laya** ([card](https://huggingface.co/convaiinnovations/laya), [repo](https://github.com/NandhaKishorM/laya); Apache-2.0):
  - EN 421M on ModernBERT-large (~808–840 MB); multilingual 322M on mmBERT-base (~647 MB, PT/ES included);
  - CPU 193–464 ms; ECE 0.081 after temperature scaling;
  - the fine-tuned checkpoint reaches 0.766 typed-decision accuracy, but **the base EN checkpoint scored 0.362, below the 0.461 majority baseline** (card).
  - Too heavy to keep resident next to Qwen on 8 GB Android.
- **mmBERT-small** ([card, MIT](https://huggingface.co/jhu-clsp/mmBERT-small)): 140M (42M non-embedding), 1,800+ languages, ~70 MB int8 (est.). Needs ~1–3k labelled prompts, which Laya, the NVIDIA prompt classifier (EN only, NVIDIA Open Model License, [card](https://huggingface.co/nvidia/prompt-task-and-complexity-classifier)) or SKR-style labelling can produce.
- **semantic-router** ([MIT](https://github.com/aurelio-labs/semantic-router)): zero-model kNN over exemplar utterances, but bge-small is English-only.
- **L0:** route accuracy and macro-F1 on Compass's chat slice v0, against regex `classify.ts` and Jev.

## How this was made
- Three Opus web-scan agents (clusters A rerank/sparse/late-interaction/embedders, B rewriting/compression/enrichment/agentic, C offline Wikipedia/on-device stacks/routers). Their sources are inline above.
- Licenses for the rerankers I tested were re-checked via the Hugging Face API (`cardData.license`); all Apache-2.0.
- L0 run by Sonar on desktop. Models are in the scratchpad, not shipped: jina-tiny 67 MB, MiniLM-L6 25 MB, MiniLM-L12 68 MB, gte-modernbert 161 MB, bge-m3 438 MB (all < 1 GB).
